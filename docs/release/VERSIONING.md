# バージョニング戦略

本ドキュメントは、システムのバージョン管理方針を説明します。

---

## セマンティックバージョニング

バージョン番号は `MAJOR.MINOR.PATCH` の形式を採用します。

```
例: 2.3.5
    │ │ │
    │ │ └─ PATCH: バグ修正
    │ └─── MINOR: 新機能追加（後方互換）
    └───── MAJOR: 破壊的変更
```

---

## バージョンの決定基準

### MAJOR バージョンアップ

以下のような破壊的変更を含む場合に適用します：

- APIの破壊的変更
- データベーススキーマの大幅変更
- 主要な技術スタックの変更
- ユーザーインターフェースの全面刷新

**例**: `1.9.5` → `2.0.0`

### MINOR バージョンアップ

後方互換性を保ちながら新機能を追加する場合に適用します：

- 新機能の追加
- 既存機能の拡張
- パフォーマンス改善
- 非破壊的なAPI追加

**例**: `1.2.5` → `1.3.0`

### PATCH バージョンアップ

バグ修正やセキュリティパッチなど、既存機能の修正に適用します：

- バグ修正
- セキュリティパッチ
- ドキュメント修正
- 軽微なUI調整

**例**: `1.2.3` → `1.2.4`

## バージョン管理ファイル

### フロントエンド (package.json)

```json
{
  "name": "attendance-system-frontend",
  "version": "1.2.3",
  "description": "勤怠管理システム フロントエンド"
}
```

### バックエンド (package.json)

```json
{
  "name": "attendance-system-backend",
  "version": "1.2.3",
  "description": "勤怠管理システム バックエンド"
}
```

### バージョン情報の埋め込み

アプリケーション内でバージョン情報を参照できるようにします：

```typescript
// src/config/version.ts
export const VERSION = {
  major: 1,
  minor: 2,
  patch: 3,
  full: '1.2.3',
  buildDate: '2024-12-19',
  gitCommit: process.env.VITE_GIT_COMMIT || 'unknown'
};
```

## バージョン更新コマンド

### npm version コマンド

```bash
# MAJOR バージョンアップ
npm version major

# MINOR バージョンアップ
npm version minor

# PATCH バージョンアップ
npm version patch
```

### 手動でのバージョン更新

```bash
# package.json を直接編集
# バージョン番号を変更
npm install  # package-lock.json を更新
```

---

## ベストプラクティス

1. **一貫性**: すべてのパッケージで同じバージョン番号を使用
2. **明確性**: バージョンアップの理由を明確に文書化
3. **透明性**: CHANGELOG.md でバージョン変更内容を記録
4. **自動化**: CI/CDパイプラインでバージョンチェックを実装
5. **コミュニケーション**: バージョンアップ内容をチームに共有
