# ドキュメント構造規約

このドキュメントは、プロジェクト全体で統一されたドキュメントの構造と記述方法を定義します。

## 基本構造

- 見出しは階層的に整理する
- 目次は必要に応じて追加する
- 関連ドキュメントへのリンクを含める

## Markdown規約

### 1. 見出し

- `#` の後には必ず半角スペースを入れる
- 見出しレベルは飛ばさない（`#` → `###` はNG、`#` → `##` はOK）

### 2. リスト

- リストの記号の後には半角スペースを入れる
- ネストする場合は2スペースインデント

```markdown
- 項目1
  - サブ項目1
  - サブ項目2
- 項目2
```

### 3. コードブロック

- 言語を指定する
- 説明が必要な場合は前後にコメントを入れる

````markdown
```javascript
// ログイン処理の例
function login(username, password) {
  // ...
}
```
````

### 4. リンク

- 相対パスを使用する（リポジトリ内のファイル）
- 外部リンクは絶対URLを使用する

```markdown
[ユーザーマニュアル](docs/MANUAL.md)
[GitHub](https://github.com)
```

### 5. 画像

- 説明的な代替テキストを必ず付ける
- 画像は`docs/user/images/`ディレクトリに配置

```markdown
![ログイン画面](images/login-screen.png)
```

## 箇条書きの活用

```markdown
## 機能一覧
- ユーザー認証
  - ログイン
  - ログアウト
  - パスワードリセット
- 勤怠管理
  - 出勤打刻
  - 退勤打刻
  - 履歴閲覧
```

## ドキュメントの種類別ガイドライン

### ユーザー向けドキュメント

- **対象者**: エンドユーザー（技術的知識が少ない人も含む）
- **口調**: 丁寧語（です・ます調）
- **内容**: 手順を明確に、スクリーンショットを多用

### 開発者向けドキュメント

- **対象者**: 開発者
- **口調**: 簡潔で技術的な表現
- **内容**: 技術的詳細、アーキテクチャ、API仕様など

### リリースノート

- **対象者**: すべてのステークホルダー
- **口調**: 簡潔かつ明確
- **内容**: 変更点、新機能、既知の問題、アップグレード手順
