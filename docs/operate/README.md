## 概要

サーバーレス構成の採用により、従来のサーバー運用タスクの多くが不要となり、アプリケーションとデータの管理に注力できます。

---

## 運用の基本方針

### 運用原則

1. **自動化優先**: 手動作業を最小限に
2. **監視重視**: 問題の早期検知
3. **予防保全**: 問題発生前の対応
4. **コスト管理**: 無駄なリソースの削減
5. **セキュリティ**: 継続的な脆弱性対応

### サーバーレスによる運用負荷軽減

**不要となった作業**:
- サーバーOSのパッチ適用
- ミドルウェアのアップデート
- サーバー監視・再起動
- スケーリング設定の手動調整
- ハードウェア障害対応

**必要な運用作業**:
- アプリケーションコードの保守
- データベースのメンテナンス
- ログとメトリクスの監視
- コスト最適化
- セキュリティ対応

## 環境別運用戦略

### 1. 開発環境（ローカル）
**運用方針**:
- 開発者が各自管理
- Docker Compose で環境リセット可能
- コスト: ゼロ

**主な作業**:
- 開発用データのリセット
- Docker イメージの更新
- ローカル環境のトラブルシューティング

### 2. CI環境（GitHub Actions）
**運用方針**:
- 完全自動化
- LocalStack で環境自動作成・削除
- コスト: GitHub無料枠内

**主な作業**:
- ワークフローDev定義の保守
- シークレット管理
- ビルド時間の最適化

### 3. 検証・ステージング・本番環境（AWS）
**運用方針**:
- AWS管理サービス活用
- 自動化と監視による最小限の介入
- コスト監視と最適化

**主な作業**:
- Lambda 関数の監視
- DynamoDB の容量モード調整
- ログの確認とアラート対応
- コスト分析と最適化
- セキュリティパッチ適用（アプリケーション層のみ）

## サーバーレス特有の運用ポイント

### Lambda 運用
- コールドスタート時間の監視
- 同時実行数の監視と制限設定
- タイムアウトエラーの分析
- メモリ使用率の最適化

### Aurora Serverless 運用
- ACU使用量の監視
- スケーリングイベントの確認
- スロークエリの検出と改善
- 接続数の監視

### コスト管理
- 日次コストレポートの確認
- 異常なコスト増加の検知
- 未使用リソースの削除
- リザーブドキャパシティの検討（本番のみ）
