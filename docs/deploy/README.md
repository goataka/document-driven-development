## 概要

本システムのデプロイメントは、環境ごとに最適な構成を採用し、コスト効率と運用負荷の最小化を実現します。

### デプロイメントの基本方針

- **環境分離**: ローカル、CI、検証、ステージング、本番の5環境
- **自動化**: CI/CDによる完全自動デプロイ
- **コスト最適化**: サーバーレス構成で従量課金を活用
- **セキュリティ**: 環境ごとの適切なアクセス制御
- **可観測性**: すべての環境で監視とログを統一

---

## デプロイメント方針

### 基本原則

1. **Infrastructure as Code**: すべてのインフラをコード管理
2. **イミュータブルインフラ**: デプロイ時は常に新規作成
3. **ブルーグリーンデプロイ**: ゼロダウンタイムデプロイ
4. **自動ロールバック**: 問題検知時の自動復旧
5. **段階的リリース**: カナリアリリースによるリスク低減

## 環境構成

### 1. 開発環境（ローカル）

**方針**:
- Docker Composeで全サービスを実行
- 開発者のマシン上で完結
- コストゼロ

**構成**:
- フロントエンド: Vite開発サーバー
- バックエンド: NestJS開発サーバー
- データベース: PostgreSQLコンテナ
- その他: Redisコンテナ（必要時）

### 2. CI環境（GitHub Actions）

**方針**:
- TestContainersで独立環境
- すべてのPRで自動実行
- GitHub無料枠内で運用

**構成**:
- ランナー: GitHub提供Ubuntu
- コンテナ: TestContainersでDB起動
- 成果物: ビルド済みアーティファクト

### 3. 検証環境（AWS）

**方針**:
- 開発チーム内テスト用
- 最小コストで運用
- 自動デプロイ（main ブランチ）

**構成**:
- フロントエンド: S3 + CloudFront
- バックエンド: Lambda（従量課金）
- データベース: Aurora Serverless v2（最小容量）
- 監視: CloudWatch（無料枠）

**コスト目安**: 月額 $10-20

### 4. ステージング環境（AWS）

**方針**:
- 本番環境と同等構成
- リリース前の最終検証
- 低コスト運用

**構成**:
- フロントエンド: S3 + CloudFront
- バックエンド: Lambda（従量課金）
- データベース: Aurora Serverless v2（最小容量）
- 監視: CloudWatch（無料枠）

**コスト目安**: 月額 $15-30

### 5. 本番環境（AWS）

**方針**:
- 高可用性とパフォーマンス
- 自動スケーリング
- コスト最適化

**構成**:
- フロントエンド: S3 + CloudFront（エッジキャッシュ）
- バックエンド: Lambda（自動スケーリング）
- データベース: Aurora Serverless v2（オートスケーリング）
- 監視: CloudWatch + X-Ray
- CDN: CloudFront（低コストグローバル配信）

**コスト目安**: 月額 $30-100（トラフィック次第）

## インフラストラクチャ戦略

### サーバーレス構成の採用理由

1. **コスト最適化**:
   - 使用量に応じた従量課金
   - アイドル時のコストゼロ
   - サーバー管理コストの削減

2. **運用負荷の軽減**:
   - サーバー保守不要
   - OSパッチ適用不要
   - 自動スケーリング

3. **高可用性**:
   - AWS管理の冗長化
   - 自動フェイルオーバー
   - マルチAZ構成

### 技術選定

- **Lambda**: バックエンドAPI（Node.js 20ランタイム）
- **Aurora Serverless v2**: PostgreSQL互換DB
- **S3**: 静的ファイルホスティング
- **CloudFront**: CDN（低レイテンシ配信）
- **API Gateway**: APIエンドポイント管理（オプション）
- **CloudWatch**: ログとメトリクス（無料枠活用）

### Docker Compose方針（ローカル・CI）

**ローカル開発**:
- すべてのサービスをコンテナ化
- docker-compose.ymlで一括管理
- ボリュームマウントでホットリロード

**CI環境**:
- TestContainersでテスト用DB起動
- 各テスト実行後に自動クリーンアップ
- 並列実行で高速化
