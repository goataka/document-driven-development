# バックエンドデプロイ方針

本ドキュメントは、バックエンドのデプロイ方針とサーバーレス戦略を説明します。

---

## デプロイ方針

### 基本戦略

**サーバーレス構成（AWS Lambda）の採用**:
- コスト最適化: 実行時間に応じた従量課金
- 自動スケーリング: トラフィックに応じた自動拡張
- 運用負荷軽減: サーバー管理不要

### 環境別デプロイ方針

#### 1. ローカル環境
- Docker Composeで NestJS サーバーを起動
- ホットリロード有効で開発効率化
- LocalStackでDynamoDBをエミュレート

#### 2. CI環境
- LocalStackでテスト用環境構築
- 統合テスト完了後に自動クリーンアップ
- ビルド成果物をアーティファクトとして保存

#### 3. 検証・ステージング・本番環境（AWS）
- Lambda関数としてデプロイ
- API Gatewayでエンドポイント管理（オプション、[ADR-012](../../specs/architecture/012-api-gateway-integration.md)参照）
- DynamoDBと接続

## Lambda デプロイ戦略

### パッケージング方針
- NestJSアプリケーションをLambda対応形式にバンドル
- 必要な依存関係のみを含める（サイズ最小化）
- 環境変数で設定を注入

### 実行環境
- ランタイム: Node.js 20
- メモリ: 512MB-1024MB（負荷に応じて調整）
- タイムアウト: 30秒（API用途）
- 同時実行数: 10-100（環境に応じて制限）

### コールドスタート対策方針
- Provisioned Concurrencyの検討（本番環境のコールドスタート対策、[ADR-013](../../specs/architecture/013-lambda-provisioned-concurrency.md)参照）
- 軽量な初期化処理
- 接続プールの適切な管理

---

## Docker Compose 方針（ローカル）

### ローカル開発
**目的**: 
- 開発環境の一貫性確保
- 依存サービスの簡単な起動

**構成方針**:
```yaml
services:
  - backend: NestJSアプリケーション
  - localstack: DynamoDB/S3エミュレーション
  - redis: セッション管理（オプション、[ADR-004](../../specs/architecture/004-redis-cache-usage.md)参照）
```

### LocalStack の活用
**目的**:
- AWS サービスのローカルエミュレーション
- コストゼロでの開発・テスト

**使用方針**:
- DynamoDBのローカルエミュレーション
- S3のローカルエミュレーション（オプション、[ADR-014](../../specs/architecture/014-s3-local-emulation.md)参照）
- AWS SDKと完全互換

## デプロイフロー

### 自動デプロイ
1. コードプッシュ → GitHub Actions実行
2. ビルド・テスト実行
3. Lambda関数パッケージ作成
4. AWS Lambda更新（環境別）
5. ヘルスチェック実行
6. 問題時は自動ロールバック

### 手動承認（本番のみ）
- ステージング検証完了後
- 承認者のレビュー必須
- デプロイ実行

---

## セキュリティ方針

- IAMロールによる最小権限
- VPC内でのLambda実行（DB接続時）
- シークレット管理: AWS Secrets Manager
- 環境変数の暗号化

---

## コスト最適化

- Lambda実行時間の最小化
- 不要なログ出力の削減
- 適切なメモリ設定（コスト vs パフォーマンス）
- 開発環境はコスト追跡タグ付与
