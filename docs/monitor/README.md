## 概要

サーバーレス構成における監視は、従来のサーバー監視から、アプリケーションとビジネスメトリクスの監視に重点を移します。

### 監視の目的

- **可用性監視**: サービスの正常稼働確認
- **パフォーマンス監視**: レスポンスタイム、スループット
- **エラー監視**: アプリケーションエラーと例外
- **コスト監視**: AWS利用料金の追跡
- **セキュリティ監視**: 不正アクセスや異常動作の検知

---

## 監視方針

### 基本原則

1. **早期検知**: 問題を即座に発見
2. **自動アラート**: 閾値超過時の自動通知
3. **可視化**: ダッシュボードで一目で状況把握
4. **コスト最適化**: 無料枠とオープンソースツール活用
5. **統合管理**: すべての環境を統一的に監視

### サーバーレス特有の監視ポイント

**Lambda 監視**:
- 実行時間とタイムアウト
- コールドスタート頻度
- エラー率と成功率
- 同時実行数

**DynamoDB 監視**:
- 読み取り/書き込みキャパシティ使用量
- スロットリングエラー
- レイテンシ
- テーブルサイズとアイテム数
- GSI/LSIの使用状況

**CloudFront 監視**:
- キャッシュヒット率
- リクエスト数とトラフィック
- エラー率（4xx, 5xx）
- レイテンシ

## 環境別監視戦略

### 1. 開発環境（ローカル）
**監視方針**:
- 開発者のローカルログ確認のみ
- コスト: ゼロ

**手段**:
- コンソールログ出力
- Dockerログ確認
- 開発者ツール（ブラウザ）

### 2. CI環境（GitHub Actions）
**監視方針**:
- ビルド・テスト結果の記録
- GitHub Actions標準機能のみ

**手段**:
- GitHub Actions ログ
- テスト結果レポート
- カバレッジレポート

### 3. 検証環境（AWS）
**監視方針**:
- 基本的なエラー監視
- コスト監視

**手段**:
- CloudWatch Logs（無料枠）
- CloudWatch メトリクス（無料枠）
- コストエクスプローラー

### 4. ステージング環境（AWS）
**監視方針**:
- 本番同等の監視
- アラート設定（重要度低）

**手段**:
- CloudWatch フル活用
- X-Ray（トレーシング）
- エラー追跡ツール

### 5. 本番環境（AWS）
**監視方針**:
- 包括的な監視
- 即座のアラート通知

**手段**:
- CloudWatch（ログ・メトリクス・アラーム）
- X-Ray（分散トレーシング）
- Sentry（エラー追跡、無料プラン）
- カスタムダッシュボード

## 監視ツールスタック

### AWSネイティブサービス（優先）

| ツール | 用途 | コスト |
|--------|------|--------|
| **CloudWatch Logs** | ログ収集・保存 | 無料枠あり |
| **CloudWatch Metrics** | メトリクス収集 | 無料枠あり |
| **CloudWatch Alarms** | アラート通知 | 低コスト |
| **X-Ray** | 分散トレーシング | 無料枠あり |
| **CloudWatch Dashboards** | 可視化 | 低コスト |
| **Cost Explorer** | コスト分析 | 無料 |

### 外部ツール（補完）

| ツール | 用途 | コスト |
|--------|------|--------|
| **Sentry** | エラー追跡 | 無料プラン（5K events/月） |
| **UptimeRobot** | 死活監視 | 無料プラン（50監視） |

## アラート戦略

### アラートレベル

1. **Critical**: 即座の対応が必要（本番停止レベル）
2. **Warning**: 監視が必要（閾値接近）
3. **Info**: 情報通知（傾向把握）

### 通知先

- **Critical**: Slack + メール + SMS（本番のみ）
- **Warning**: Slack + メール
- **Info**: Slackのみ

### 主要アラート項目

**Lambda**:
- エラー率 > 5%
- 平均実行時間 > 3秒
- タイムアウト発生

**Aurora Serverless**:
- ACU使用率 > 80%
- 接続数 > 設定値の80%
- スロークエリ検出

**CloudFront**:
- エラー率（5xx） > 1%
- キャッシュヒット率 < 80%

**コスト**:
- 日次コスト > 予算の150%

## コスト最適化

### ログ保持期間の最適化
- 本番: 30日
- ステージング: 14日
- 検証: 7日

### メトリクスの最適化
- 必要なメトリクスのみ収集
- カスタムメトリクスは最小限
- 集約期間の適切な設定

### アラームの最適化
- 重複アラームの削減
- 適切な閾値設定
- 不要なアラームの削除
